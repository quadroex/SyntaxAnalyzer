# MiniCpp

Навчальний синтаксичний аналізатор підмножини C++ на основі Flex і Bison. Проєкт перетворює вихідний текст на абстрактне синтаксичне дерево AST, перевіряє його, виконує програму та генерує JavaScript. У браузері можна переглянути дерево й порівняти результати двох способів виконання.

Виконавець - Грицина Антон Олександрович, група ТТП-32.

Вхідні програми використовують підмножину C++. Аналізатор реалізований на C++17, а цільовою мовою трансляції є JavaScript.

## Як працює аналізатор

```text
C++ source -> Flex lexer -> Bison parser -> AST -> Semantic analysis
                                                   |
                                                   +-> AST interpreter
                                                   +-> JavaScript generator
```

### Лексичний аналіз

У [src/lexer.l](src/lexer.l) задані регулярні вирази для чисел, ідентифікаторів, ключових слів та операторів. Flex генерує з цих правил код лексера. Під час роботи він об'єднує символи у токени, пропускає пробіли й коментарі та зберігає рядок і позицію кожного токена для повідомлень про помилки.

### Граматика й побудова AST

[src/parser.y](src/parser.y) описує правила граматики та дії, які виконуються під час їх згортання. Bison генерує LALR(1)-парсер на C++. Наприклад, правило `expression '+' expression` створює вузол `Binary` із двома дочірніми виразами. Пріоритети й асоціативність операторів задаються директивами Bison, а неоднозначність вкладених `if/else` усувається окремим пріоритетом `else`.

Вузол `Node` зберігає вид операції, текст, дочірні вузли та позицію у вихідній програмі. Після семантичної перевірки він також містить тип і номер символу. Усі вузли належать `Context` і зберігаються через `std::unique_ptr`, тому пам'ять звільняється автоматично. Опис цих структур розміщено у [src/core.hpp](src/core.hpp).

### Семантична перевірка

[src/semantic.cpp](src/semantic.cpp) обходить AST і веде стек областей видимості. Для кожного оголошення призначається номер символу, за яким інтерпретатор і генератор потім знаходять потрібну змінну. Так однойменні змінні у вкладених блоках залишаються окремими. На цьому етапі також перевіряються типи виразів, параметри функцій, індекси масивів і допустимість `return`, `break` та `continue`.

### Виконання дерева

[src/interpreter.cpp](src/interpreter.cpp) обчислює вирази рекурсивним обходом AST і виконує оператори відповідно до виду вузла. Кожен виклик функції отримує окремий кадр із параметрами й локальними значеннями. Повернення з функції та переходи в циклах передаються через структуру `Flow`. Параметри-масиви використовують спільне сховище елементів, тому функція може змінювати переданий масив.

### Генерація JavaScript

[src/generator.cpp](src/generator.cpp) обходить перевірене дерево й формує текст цільової програми. Змінні та функції отримують назви за номерами символів. До результату додаються службові функції для числових перетворень, цілочисельного ділення, введення, виведення й перевірки помилок. Це зберігає потрібну поведінку вхідної мови під час виконання у JavaScript. Згенерований файл можна запустити через Node.js окремо від аналізатора.

## Вебінтерфейс

[server.py](server.py) використовує стандартну бібліотеку Python і запускає локальний HTTP-сервер. Браузер надсилає вихідний текст та дані вводу у JSON. Для кожного запиту сервер запускає окремий процес аналізатора й повертає AST, згенерований код і результат інтерпретації.

[web/app.js](web/app.js) малює дерево елементами SVG. Вузли можна розгортати, згортати, масштабувати та вибирати для переходу до відповідного рядка програми. Окрему гілку можна показати через `Focus selected`. Згенерований JavaScript виконується у Web Worker, після чого інтерфейс порівнює його результат із результатом інтерпретатора. Зовнішні бібліотеки JavaScript і доступ до інтернету для роботи сторінки не потрібні.

## Встановлення й запуск

Потрібні Linux або WSL Ubuntu, компілятор `g++` з підтримкою C++17, Flex, Bison 3.8 або новіший, GNU Make 4.3 або новіший і Python 3. Для перевірок та окремого виконання цільового коду потрібен Node.js.

В Ubuntu залежності можна встановити наведеною командою.

```bash
sudo apt update
sudo apt install g++ make flex bison python3 nodejs
```

Для запуску в Linux або WSL виконати наведені команди.

```bash
git clone https://github.com/quadroex/SyntaxAnalyzer.git
cd SyntaxAnalyzer
make
python3 server.py
```

Відкрити у браузері `http://127.0.0.1:8765`, вибрати приклад і натиснути `Analyze & run`. Кнопка `Run JavaScript` запускає перекладену програму, а `Results match` показує збіг результатів.

У Windows зі встановленими залежностями у WSL достатньо запустити [Start.cmd](Start.cmd). Скрипт визначає шлях до проєкту, збирає його у WSL і відкриває браузер. Вікно запуску потрібно залишати відкритим. Для зупинки сервера використовується Ctrl+C.

Якщо порт зайнятий, у PowerShell з папки проєкту можна вибрати інший.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8766
```

Задачі збирання, запуску й перевірки для VS Code наведено у [.vscode/tasks.json](.vscode/tasks.json).

## Використання з командного рядка

```bash
./build/minicpp check examples/01_sum.cpp
./build/minicpp run examples/03_factorial.cpp
./build/minicpp ast examples/01_sum.cpp
./build/minicpp compile examples/03_factorial.cpp > build/factorial.js
node build/factorial.js
```

Команда `check` перевіряє програму, `run` виконує AST, `ast` повертає дерево у JSON, а `compile` створює JavaScript. Команда `analyze` поєднує ці результати у JSON для вебінтерфейсу. У прикладі з факторіалом обидва способи виконання виводять `120`.

Дані для `cin` можна передати окремим аргументом. Згенерований файл отримує їх зі стандартного вводу Node.js.

```bash
./build/minicpp run examples/08_array_input.cpp --input "5 4 1 5 2 3"
./build/minicpp compile examples/08_array_input.cpp > build/array.js
printf '5 4 1 5 2 3\n' | node build/array.js
```

## Межі вхідної мови

Граматика охоплює числові типи, локальні змінні, вирази, розгалуження, цикли, функції з рекурсією, одновимірні масиви та числове введення. Підтримується визначена навчальна підмножина C++. Її синтаксис, особливості виконання й обмеження описано у [docs/LANGUAGE.md](docs/LANGUAGE.md). Приклади правильних програм і помилок розміщено у [examples](examples).

## Збирання й перевірка

[Makefile](Makefile) спочатку запускає Bison і Flex, а потім компілює їхній результат разом із власними файлами C++. Створені файли зберігаються у `build/` і відтворюються під час збирання. Нерозв'язані конфлікти shift/reduce та reduce/reduce спричиняють помилку збирання. Звіт зі станами парсера й розв'язаними конфліктами записується у `build/parser.output`.

Для перевірки виконати `make test` або запустити [Verify.cmd](Verify.cmd) у Windows. Тести на стандартному модулі Python `unittest` порівнюють результати інтерпретатора, згенерованого JavaScript і програм, зібраних GCC. Окремо перевіряються форма AST, повідомлення про помилки, області видимості, масиви й обмеження виконання.

## Складність під час розробки

Під час порівняння результатів виникла розбіжність у форматуванні дробових чисел між C++ і JavaScript. Звичайне перетворення числа на рядок давало іншу кількість значущих цифр, а на граничних значеннях відрізнялося округлення. Для цільового коду додано окрему функцію форматування до шести значущих цифр, а до тестів - відповідні граничні приклади з порівнянням виведення GCC. Це дозволило узгодити результати обох виконавців.
